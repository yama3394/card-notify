セルフホスト型・家計通知ツール

カードの利用通知を、
毎日LINEで家計簿に。

クレジットカードの利用通知メールを自動で読み取り、その日の支出サマリを毎朝LINEへ。家計簿への登録作業はほぼゼロに。データは自分のサーバーの中だけに残ります。

  • 自分のサーバーで完結。データはどこにも預けません
  • 広告・課金なし。MIT ライセンスの無償ソフトです
  • 普段使っている Gmail と LINE だけで動きます

ほかの家計簿との違い

「記録する」を、やめられる。

家計簿が続かない一番の理由は、レシート撮影や金額の手入力といった「記録の手間」。card-notify は、カードを使うたびに届く利用通知メールを自動で取り込むので、支出は使った直後から勝手に家計簿へ載っていきます。登録作業そのものが、ほぼなくなります。

手入力の家計簿アプリ

  • ✕レシートを撮って、金額と店名を打ち込む
  • ✕入力を忘れた日から記録が歯抜けになる
  • ✕続けるほど「毎日の作業」が積み上がる

card-notify

  • ✓カード決済は利用通知メールから全自動で登録。入力ゼロ
  • ✓使った直後に記録されるので、抜け漏れが起きない
  • ✓あなたがやるのは、現金支出の金額を LINE に送ることだけ

口座連携型の家計簿サービスとも違い、金融機関のログイン情報を外部に預けたり、連携切れのたびに再認証したりする必要はありません。使うのは Gmail の読み取り専用権限（gmail.readonly）だけ。取り込んだ家計データは、すべて自分のサーバーの中に残ります。

できること

通知メールから、使える家計データへ。

受信箱に届く利用通知を集計し、毎日の支出を追える形にします。誇張のない、実際にある機能だけを。

LINE 自動通知

日次・週次・月次の支出サマリを LINE にプッシュ。現金支出は LINE のトークに金額を送るだけで手入力できます。

WebUI で家計管理

ログイン制のダッシュボードで取引一覧を確認・編集。CSV エクスポートと通知時刻の変更もブラウザから。

外貨決済に対応

外貨の利用は円合計に混ぜず、通貨ごとに分けて集計。海外利用やサブスクの内訳がぶれません。

プラグイン式パーサ

カード会社ごとのメール解釈は parsers/ に1ファイル追加するだけ。標準で三井住友カードと JCB の実装例つき。未対応カードはメールを送ってもらえれば追加対応。

自動アップデート

配信元をポーリングして安全に更新。失敗したときは自動でロールバックし、動く状態を保ちます。

セルフホスト＝プライバシー

各自が自分の Google / LINE / サーバーで運用。金融データは自分のサーバー内に残り、他人に預けません。

はじめ方

4ステップで動きはじめる。

自分の環境で動かすツールなので、いくつか自分で用意するものがあります。各ステップの詳細は README に。

常時起動はしますが、実際の処理は1日数回のメール取得とLINE送信だけ。データベースは使わず軽量な JSON ファイルに保存するので、必要なスペックは控えめです。目安は以下のとおりです。

項目 オンプレミス（自宅サーバー・VPS） AWS Oracle Cloud（Always Free）
CPU 1 vCPU（x86_64 / ARM64 どちらでも可） t4g.micro（Arm, 2 vCPU）または t3.micro（x86, 2 vCPU） Ampere A1（Arm, 最大4 OCPU）または VM.Standard.E2.1.Micro（x86）のいずれも無料枠内
メモリ 1GB 以上（512MB でも動作しますが余裕を見て推奨） 1GB（上記インスタンスタイプに標準搭載） 1GB〜（Ampere A1 は無料枠のまま最大24GBまで割当可能）
ディスク 空き 5GB 以上 EBS gp3 8GB 程度 ブロックボリューム 50GB 程度（無料枠 200GB の範囲内）
OS Linux（Debian / Ubuntu 系推奨）・systemd 必須 Ubuntu Server AMI または Amazon Linux 2023 Ubuntu（Arm/x86 両対応イメージ）
ネットワーク 固定 IP または DDNS、443/80 番ポートを開放、独自ドメイン Elastic IP を1つ割り当て、セキュリティグループで 443/80 を開放（22 は管理者 IP のみに限定） パブリック IP は標準付与。セキュリティリスト（クラウド側）とインスタンス内 iptables/firewalld（OS側）の両方で 443/80 を開放する必要あり

いずれの環境でも、Gmail・LINE との通信および証明書更新のために常時インターネット接続が必要です。AWS では固定月額プランの Lightsail でも同程度のスペックで問題なく動作します。Oracle Cloud の Always Free は無料枠のまま永続利用でき、本アプリの依存パッケージはいずれも Arm64（Ampere A1）向けの配布がありインストールに支障ありません。

サーバーを用意

インターネットに常時接続された Linux サーバー（Python 3.10+）と、HTTPS 終端できるリバースプロキシ。LINE Webhook は HTTPS が必須です。

Google と LINE を連携

Google Cloud で Gmail API の OAuth を設定し、LINE Messaging API のチャンネルを作成。トークンを控えておきます。

セットアップを実行

install.sh または python setup.py の対話ウィザードで、パスワード・トークン・鍵を設定して .env を生成します。

通知時刻を設定

WebUI にログインし、日次通知の時刻を指定。あとは毎朝、支出サマリが LINE に届きます。

nginx / systemd / cron の具体的な設定を含む詳細な手順は README にまとめています。

未対応カードの追加

あなたのカードも、追加対応します。

標準対応（三井住友カード・JCB）以外のカードでも、利用通知メールの本文（テキスト）またはスクリーンショットを送ってもらえれば、パーサを追加して対応します。金額・日付・利用先の書式がわかれば十分です。

送る前に、カード番号・氏名などの個人情報は必ず伏せて（塗りつぶして）ください。

メールで送る

本文を貼り付けるか、スクリーンショットを添付してそのまま送信してください。対応後は自動アップデート経由で全インストールに配信されます。

FAQ

先に知っておきたいこと。

セルフホストならではの前提と落とし穴を、正直に書いておきます。

自分で用意するものは？

常時インターネットに接続された Linux サーバー、Google Cloud の OAuth 設定（Gmail API）、そして LINE Messaging API のチャンネルの3つです。いずれもあなた自身のアカウントで用意します。運用はすべて自分のサーバー内で完結します。オンプレミス・AWS それぞれの推奨スペックは セットアップの節 にまとめています。

通知が数日で止まってしまいます

Google の OAuth 同意画面を「テスト中」のままにしていると、Gmail の refresh token が約7日で失効し、通知が静かに止まります。長期運用では同意画面を「本番」に切り替えるのが必須です。詳細は README のセットアップ節を参照してください。

対応しているカードは？

標準では三井住友カードとJCBの実装例が同梱されています。他社カードや銀行に対応するには、parsers/ にパーサを1ファイル追加します。自分で書かなくても、利用通知メールの本文かスクリーンショットを送ってもらえれば追加対応します（個人情報は伏せて送ってください）。

データはどこに保存される？

取引履歴も認証情報も、あなたのサーバー内にだけ保存されます。card-notify に外部へデータを送る仕組みはありません。他人にデータを預けたくない人のための設計です。

更新はどうなりますか？

配信元をポーリングして自動で更新できます。更新に失敗した場合は自動でロールバックし、直前の動く状態に戻します。

ライセンスと保証は？

MIT ライセンス・無保証です。自分の受信箱と金融情報を扱うツールなので、内容を理解したうえで自己責任で運用してください。.env や認証ファイルは公開リポジトリにコミットしないよう注意してください。

アンインストールしたい場合は？

専用の uninstall.sh を用意しています。サーバー上で curl -fsSL https://card-notify.yama3394.uk/uninstall.sh -o uninstall.sh && sudo bash uninstall.sh を実行すると、systemd サービス・専用ユーザー・アプリ本体（/opt/card-notify）を削除します。

既定では取引データ・LINE/Gmail 連携情報・WebUI パスワードが入った /var/lib/card-notify は誤削除防止のため保持されます。完全に削除したい場合は sudo PURGE_DATA=true bash uninstall.sh を実行するか、/var/lib/card-notify を手動で削除してください。
